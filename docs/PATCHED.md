# Patched bindings

The bindings are generated by [runic](https://github.com/Samudevv/runic) from the C headers.
Regenerating overwrites hand fixes, so each is also pinned by a typed variable in the
package's `patched.odin`: a regeneration that drops a patch fails to compile there instead
of misbehaving at run time.

To regenerate, run `make generate` and then `make ci`.

## Generation rules

`scripts/postprocess.sh secret` applies these to `secret/secret.odin`, in this order. They are
odin-glib's rules (odin-gtk's, MIT), trimmed to what runic 0.8 produces from libsecret.

| rule | reason | pin |
|---|---|---|
| `^glib.char` becomes `cstring` | `gchar *` is a typedef'd char pointer, which runic leaves as `^char` | `patched_password_lookup_sync`, `patched_value_get_text` |
| the `secret` parameter of `value_new` and `value_new_full`, and the result of `value_get`, become `^byte` | a secret is a byte buffer, not text | `patched_value_new`, `patched_value_get` |
| the attribute table is `^glib.HashTable` | one `GHashTable`, not an array; `to.detect.parameters: declared` in `secret/rune.yml` makes it so, where runic 0.8 wrote `[^]` | `patched_password_storev_sync` |
| `^glib.List` (`objects` of `service_lock`, `service_lock_sync`, `service_unlock`, `service_unlock_sync`; `items` of `item_load_secrets`, `item_load_secrets_sync`) | `GList *` is one list head; `parameters: declared` makes it `^T` where runic 0.8 wrote `[^]` for a name ending in "s". `scripts/check-generated.sh` holds the list | `patched_service_lock`, `patched_item_load_secrets_sync` |
| `attributes_buildv` is not bound | its last C parameter is a `va_list`: runic 0.8 drops it and writes `#c_vararg ..any`, a wrong call; the fork skips the procedure and leaves a comment (odin-glib DECISIONS §11) | `scripts/check-generated.sh` |
| `ERROR`, `TYPE_*` and the version macros lose backticks, parentheses and the `secret_` prefix, so `TYPE_FOO` names `foo_get_type` | macro text runic quotes as a string | `patched_type_value`, `patched_error` |
| `Foo :: _SecretFoo` is deleted and `_SecretFoo` becomes `Foo` | one name per struct | |
| the `et_` prefix of the callback types in `ServiceClass` becomes `get_` | the `g` trim ate the `g` of `get_` | |
| the GFlags enums listed in `postprocess.sh` (`secret_flags`) become `FooBit :: enum u32` of bit indices plus `Foo :: bit_set[FooBit; u32]`; zero members become constants of `Foo` (`SEARCH_NONE`, `SCHEMA_NONE`, …) | `{.SEARCH_ALL, .SEARCH_UNLOCK}` instead of integer ORs; the size and bits are those of C; see DECISIONS §2 | `test_flag_bits_match_the_header` |

The pointer audit read the header for every `[^]` parameter whose name ends in `s`: the six
`GList *` parameters above are corrected, and none is left as `[^]`. Every other `[^]` in the
output is a real array.
